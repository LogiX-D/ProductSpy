# 平台统一 AI 渠道

管理员在 /settings/ai 管理渠道、密钥、模型白名单、默认项和兼容参数。用户在商品分析、竞品分析和内容创作中选择渠道与模型。支持的 13 个服务商预设及自定义兼容接口见[官方接口来源](ai-provider-sources.md)；协议支持不代表已经实测所有服务商、地域和模型。

## 运维启用

1. 用独立迁移连接执行 pnpm db:migrate。新表 ai_channel_settings 保存平台配置，属于全局服务配置；六张租户业务表的隔离规则保留。应用角色仍须 NOSUPERUSER/NOBYPASSRLS，并按 scripts/saas/app-role.sql 授予新表所需权限。
2. 设置 PRODUCTSPY_AI_ADMIN_IDS 为经确认的管理员账号 UUID，多个用逗号分隔。没有指定 ID 时任何普通账号都不能管理渠道；不使用未经核验的邮箱或客户端角色决定管理员身份。
3. 在 Web 与 Worker 的秘密配置中设置同一个独立的 PRODUCTSPY_AI_CHANNEL_SECRET，至少 32 个随机字符。主密钥不要进 Git、浏览器或插件，并单独备份；丢失或更换后旧密文无法解密，系统会停止，不能直接回退到别的真实渠道。
4. 管理员登录配置渠道。密钥只在提交时发送给服务端，读取接口只返回“是否已配置”；留空保留旧密钥。修改服务商或 API 地址必须重新输入密钥。保存不会探测提供商，也不会自动生成或产生 AI 调用。
5. AI_MODE=mock 是关闭全部真实渠道的总开关。获准使用真实服务后，将 Web 与 Worker 都设为 AI_MODE=auto，用户才能选择已启用的真实渠道。配置真实凭据与允许测试费用是两个独立条件，不能把配置保存当成真实调用验收。

旧的 AI_API_KEY/AI_BASE_URL/AI_MODEL 单渠道环境配置在没有数据库渠道配置时继续可用。首次保存平台配置后以管理员设置为准；空渠道表可以明确使用 Mock。既有 Windows/legacy 路径保留。

## 数据与调用边界

- 普通用户目录只有渠道 ID、名称、服务商、模型白名单、默认模型与 Mock/real 标记，不返回 Key、API 地址、主密钥或内部任务配置指纹。
- 新平台配置整体使用 AES-256-GCM 加密后写入 PostgreSQL。主密钥与数据库分开保存；这不等于整台主机、环境变量、所有数据库字段或备份介质已完成静态加密。
- 提交前验证白名单与真实调用确认，再预留额度。任务冻结渠道、模型与配置指纹；队列等待期间凭据、地址或调用参数改变，任务停止，不自动换渠道或重发收费 POST。更改默认项不改变已接受任务的选择。
- 历史和用量显示服务端记录的渠道/模型。内部执行快照不进入用户导出；同一服务器恢复保留已有防重复执行资料，导入文件不能提供新的执行决定。
- 整库备份需要包含加密配置表，并单独保管原加密主密钥。用户业务备份不包含平台密钥。更换管理员、撤销账号、恢复旧备份及轮换主密钥均需运维核对。

真实服务商可用性、实际费用、输出质量、额度与异常恢复必须在获授权的凭据和预算下单独验证。本地 HTTP stub、Mock 与协议契约回归都不能记为真实 AI 验收。
