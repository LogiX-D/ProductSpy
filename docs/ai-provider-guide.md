# ProductSpy AI 服务配置与分析使用指南

v0.5.1 起，远程 API 地址必须使用 HTTPS。HTTP 只接受 `localhost`、`127.0.0.1` 或 `[::1]` 本机服务；局域网 IP 也需要 HTTPS。服务端和 Windows 设置保存处均在发送请求前检查。旧版已保存的远程 HTTP 设置需要改为服务商的 HTTPS 地址；修正配置不会删除商品、分析或历史。

适用版本：v0.4.0 / Phase 12。ProductSpy 继续通过本机 Next.js 服务访问 OpenAI-compatible Chat Completions 接口。Chrome 扩展负责采集和保存，不持有 AI Key，也不能通过扩展令牌直接授权真实 AI 调用。

## 先使用本机演示

不填写 Key 时，默认 `auto` 模式使用 Mock；`mock` 始终使用本机演示。演示可完整验证分析、编辑、版本、导出和保存流程，不产生外部模型请求。中文、英文、日文结果都明确包含 Mock 标识；人工修改不会将演示素材变成真实模型结果。

Mock 是参数化模板，会根据市场、语言、平台、风格、目标和时长改变内容，但不具备真实模型的指令理解能力。自定义要求会作为人工核查备注保留，不能因此声称要求已被理解或执行。真实模型质量验证状态见 [AI 质量报告](phase12-ai-quality.md)。

## Windows 便携版设置

1. 完整解压便携包，双击 `ProductSpy.cmd` 启动。
2. 在本机控制窗口点击「AI 设置」。
3. 在「连接设置」填写模式、API 地址、模型和 Key。API 地址可为 `https://api.openai.com/v1` 一类根地址，也可直接填写 `/chat/completions` 完整地址。按服务商实际接口填写，远程服务使用 HTTPS。
4. 在「模型兼容性」根据服务商文档选择输出模式、Token 参数、超时和温度。程序不会自动试探参数或重复收费请求。
5. 点击「保存，下次启动生效」，退出 ProductSpy，再双击重新启动。

模式含义：`auto` 有 Key 时选择真实服务，否则演示；`real` 强制真实服务，未配置 Key 时会明确报错。配置 Key 或启动工作台不会自动调用模型。在工作台发起每次真实分析时，仍必须检查确认框并点击「授权本次调用」。

设置保存在独立用户目录 `%LOCALAPPDATA%\ProductSpy\settings\ai-settings.protected.json`，使用当前 Windows 用户的 DPAPI 加密，Key 输入框遮挡内容。v0.3.0 的配置可以继续读取，新兼容选项使用默认值。更换程序目录不会清空配置；更换 Windows 账户不保证能够解密。DPAPI 保护 AI 设置，不代表商品 JSON、历史结果或浏览器偏好已加密。

不要把真实 Key 写入 Git、便携包、Chrome 扩展、自定义分析要求、截图或测试报告。

## 源码运行配置

复制 `apps/web/.env.example` 为 `apps/web/.env.local`，在本机文件里填写 Key，再重启 Web。`.env.local` 属于敏感配置，不提交 Git。

```dotenv
AI_API_KEY=
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
AI_MODE=auto
AI_RESPONSE_FORMAT=json_object
AI_TOKEN_PARAMETER=max_tokens
AI_MAX_OUTPUT_TOKENS=8192
AI_TIMEOUT_MS=60000
AI_TEMPERATURE=omit
AI_DAILY_REQUEST_LIMIT=50
```

| 配置                     | 支持值与行为                                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `AI_RESPONSE_FORMAT`     | 默认 `json_object`；可显式选择 `json_schema` 或 `text`。`text` 只是不发送 `response_format`，响应正文仍必须是符合共享结构的 JSON。 |
| `AI_TOKEN_PARAMETER`     | 默认 `max_tokens`；支持显式 `max_completion_tokens`。按模型要求填写，程序不猜测全部兼容服务的支持情况。                            |
| `AI_MAX_OUTPUT_TOKENS`   | 默认 8192，范围 256–32768。限制单次输出，不是美元预算；部分模型的上限还涵盖思考 Token。                                            |
| `AI_TIMEOUT_MS`          | 默认 60000；Windows 设置和 `.env` 建议范围 1000–120000 毫秒，服务端硬上限 120 秒，低于浏览器 130 秒等待上限。                      |
| `AI_TEMPERATURE`         | 默认 `omit`，不发送温度；需要时显式填 0–2 的数值，先核对模型是否支持。                                                             |
| `AI_DAILY_REQUEST_LIMIT` | 默认每天 50 次真实请求，按 UTC 日期计数，范围 1–10000；只在源码环境变量中调整。失败、中断请求也计入。                              |

OpenAI 的 `max_tokens` 已弃用，且不适用于 o-series；`max_completion_tokens` 包含可见输出与思考 Token。本项目同时保留旧参数，服务于兼容接口，需由使用者显式选择。[OpenAI Chat Completions 官方说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

`json_schema` 使用严格对象结构、完整 `required` 和 `additionalProperties: false`。仍独立检查拒答、长度截断及返回内容，不把“有效 JSON”当作“事实正确”。不同兼容平台或模型可能不支持该模式。[OpenAI Structured Outputs 官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)

## 可控分析与事实边界

打开商品的「AI 分析」页，在「分析设置」选择：美国/英国/欧洲/日本，中文/英文/日文，TikTok/Reels/Shorts，专业/生活化/幽默/种草，15/30/60 秒，以及认知/考虑/转化目标。默认是美国、中文、TikTok、生活化、30 秒、考虑。自定义要求最多 4000 字。点击「保存分析偏好」保存到当前浏览器；不保存 Key。

发送给模型的内容只有商品文字资料、媒体数量和分析参数。默认不发送图片或视频文件，也不发送专门的图片/视频 URL 字段，不代表模型看过实物。

为控制请求规模，标题最多发送 600 字，描述最多 6000 字，卖点最多发送 12 条、每条 1000 字。出现裁剪时，「事实依据」的不确定信息明确说明分析未覆盖完整原文；本地已保存商品数据保持原样。这是字符规模控制，不是精确的输入 Token 或金额预算。

页面事实由已采集字段重新整理，模型自行声称的事实不会直接提升为事实依据。商家文案仍标为「页面宣称」。用户画像、需求、痛点、营销角度属于推断；未实测功能、质量、效果需验证。没有采集真实评论正文时，不能声称分析过用户评论。评分和评论数量仅是页面快照。结构校验及提示词不能保证模型没有幻觉，商业发布前需人工核查。

## 重新生成、历史和导出

已有分析时，可选择本次重新生成的字段。未选中的内容保持原样，已保存结果和人工修改进入版本历史；未保存草稿保留在当前标签页，不能当作长期备份。生成失败或并发保存冲突不会覆盖当前结果。局部更新可能形成不同语言、模型和人工内容的混合结果，页面和导出会标明生成范围。

当前局部生成仍请求完整模型结果，再合并选定字段；**不保证减少 Token 或费用**。使用「分析版本与比较」选择版本 A/B 查看差异、逐项复制，或恢复历史版本。恢复会创建新版本，保留原版本；不自动删除草稿。

每件商品最多 50 个历史版本，达到上限后阻止新增保存或生成，不自动删除旧结果。v0.3.0 已有分析在首次修改或重新生成时被保留为旧版历史。当前提供 Markdown/TXT 导出、整篇/分区/单项复制和历史版本导出；没有自动归档清理机制。

## 用量、费用与故障处理

「本机用量记录」读取本地账本，刷新不会调用模型。真实请求先写入预约记录再访问服务；同一请求编号不会自动重复发起，同一商品不能并行分析，全局最多 2 个真实请求。

服务商返回合法输入/输出 Token 数时记录实际数值；缺失或无效时记为未知，不按文字长度伪造实际用量。只有提供两项完整单价且返回两项 Token 数，才计算费用：

```text
估算美元费用 = 输入 Token × 输入美元单价 / 1,000,000
             + 输出 Token × 输出美元单价 / 1,000,000
```

单价在「可选：自填模型单价」填写，单位为 USD / 百万 Token。价格表不硬编码，未填写时费用未知；页面显示的已知费用合计不包含未知请求。缓存、批处理、推理规则或服务商收费项可能不同，最终以账单为准。每日次数上限不是美元消费硬上限。

| 提示                 | 处理方式                                                                               |
| -------------------- | -------------------------------------------------------------------------------------- |
| 认证失败             | 检查本机 Key、模型权限和地址，重启后再决定是否授权新请求。                             |
| 参数不支持           | 核对 JSON 模式、Token 参数、温度和模型名称；程序不自动切换或重发。                     |
| 限流/额度不足        | 检查服务商额度，等待安全解析的 `Retry-After`；缺少有效值时本机默认冷却 60 秒。         |
| 超时/网络错误        | 不自动重试。平台可能已经计费；先看服务商账单和本机记录，再决定是否手动重发。           |
| 拒答/截断/结构不完整 | 本次不保存新分析；保留旧结果，调整要求或输出上限后重新确认。                           |
| 本地账本无法读写     | 阻止新请求，保留 `analysis-usage.json`，检查磁盘权限或空间，不清空账本来掩盖未知费用。 |

响应正文有 2 MiB 上限。错误消息不透传服务商原始响应或 Key。HTTP 取消不保证服务商取消计费；费用未知不能视为免费。

## 本轮验证与限制

Provider 保留旧测试并增加本地 Stub 的兼容、证据、媒体传输、裁剪、限流、超时与结构回归。Windows 设置测试实际执行 DPAPI 加解密并读取旧配置。所有 AI 测试仅使用本机 Mock/Stub，占位 Key 不属于真实模型凭据。

本轮未获授权测试 Key 和明确预算，真实收费 API 调用为 0。正式模型、各家兼容平台和 WinForms 设置窗口人工操作仍需进一步验收；如何按预算人工验证见 [Phase 12 AI 质量报告](phase12-ai-quality.md)。
