### 已修复的 P1：远程 HTTP 传输 Key

v0.5.0 Provider 地址解析与 Windows 设置保存均接受任意远程 `http://` 地址，实际请求通过 `Authorization` 发送 Key，会缺少传输加密。这与配置指南要求远程服务使用 HTTPS 不一致。本轮通过代码审查发现并修复；验收没有使用真实 Key 重现明文泄露。

v0.5.1 已同时在 Provider 与 Windows 启动器拒绝远程 HTTP，只保留精确本机 `localhost`、`127.0.0.1` 和 `::1` 的 HTTP 供本机模型及 Stub 使用。在网络请求之前拒绝，保留原有 URL 凭据/查询/片段校验。

Provider 专项回归共 27 项通过，其中包括 8 个远程/伪装本机 HTTP 拒绝样例、4 个安全地址接受样例以及原有本机 HTTP Stub 流程。Windows 回归实际提取并执行启动器 `Assert-AiBaseUrl` 函数，验证 4 个接受、8 个拒绝和 4 个非法 URL；没有保存用户设置或发起模型请求。完整单元测试为 40 个文件、468 项通过，生产构建通过。这些结果证明地址限制和工程回归通过，不能用于评定真实模型质量。

## 授权及预算闸门

只有收到以下明确授权后才开始真实请求；Key 在本机启动器输入，不放进反馈、CSV、截图、命令参数或 Git。

1. 服务商/API 地址、确切模型和允许此次测试使用的 Key。
2. 本批最大请求数、总金额上限、币种和截止时间。
3. 测试所用真实商品、允许传输的文字及参数组合；禁止默认上传媒体。
4. 服务商真实单价与账户侧硬预算设置情况；如何核对已计费/未知请求。

建议第一批最多六个单次请求，每类一个，但这个建议不是用户授权。每天 50 次默认上限和最大输出 Token 都不能代替本批六次或金额预算。执行者应在每次点击前核对累计已发起次数与账单余额；任何中断/失败计为已发起，账单未知时暂停，禁止为了凑结果自动重试。

先在 Mock 完成配对、备份、分析版本和导出操作检查，再切换真实模式。连接设置保存或工作台启动不应触发模型。每个真实请求只通过界面授权一次，记录本机请求 ID、模型、参数、生成版本和开始/结束时间。可以对不同样本选择不同市场/语言/平台，但不能声称六个请求覆盖所有组合。

## 评分与硬失败规则

使用 [ai-scorecard.csv](ai-scorecard.csv)。六行目前均为「未执行：缺少完整授权」，评分、Token、模型、预算和账单单元格留空。空值表示未测，不能填 0 分或用 Mock 补齐。由两位熟悉商品资料与目标语言的审阅者独立填写，每位复制一组行；反馈使用匿名编号，真实身份与联系信息不提交 Git。

| 维度（1–5 分）   | 1 分                                        | 3 分                              | 5 分                                                         |
| ---------------- | ------------------------------------------- | --------------------------------- | ------------------------------------------------------------ |
| 事实准确性       | 出现无来源规格、功能、认证、效果或价格事实  | 有遗漏/含混表述，需要核查与编辑   | 关键事实可追溯，矛盾及资料缺口明确，页面宣称未冒充实测       |
| 推断与评论边界   | 把画像/痛点当作确定事实，或冒称读过真实评论 | 多数推断有说明，部分依据模糊      | 推断、验证方法、未读评论和未看媒体清楚区分                   |
| 创意具体性       | 通用套话或虚构演示                          | 有品类关联，但镜头/角度需明显补充 | 使用真实资料形成具体、可拍摄且可区分的营销角度与至少五条开场 |
| 市场与语言自然度 | 语言错误，生硬难懂或虚构当地保证            | 可理解但需较多母语编辑            | 自然口语、符合目标市场/平台语境，不猜法规或当地偏好          |
| 脚本可执行性     | 不可拍摄、虚构使用结果或明显超过时长        | 五段齐备，朗读/镜头需明显调整     | 实际朗读及镜头动作可在所选时长完成，Demo 有真实可验证拍法    |
| 自定义要求遵守   | 忽略/违背要求或突破事实安全边界             | 部分满足，需要补充                | 逐条满足已授权要求，冲突项解释清楚，无虚构承诺               |

2/4 分分别表示介于相邻等级。记录支撑评分的实际原文位置与需要修改的条数、修改分钟数，不只填主观总分。实际费用单独按账单记录，不把「价格便宜」算作品质分。

出现以下任意一项即硬失败，与总分无关：重大虚构规格/功能/认证/效果；未采评论正文却宣称已经分析用户评论；把另一个变体价格/图片当成当前 ASIN；泄露 Key 或未授权发送；无授权重复收费请求。停止该批次，保留本地证据并先核查账单及 P0/P1，不发布错误文案。

后续可采用「无硬失败、每维至少 3 分、总分至少 24/30、两名审阅者一致认可」作为小规模真实 AI 通过标准。这个门槛是待执行验收规则，当前没有测得分数，也不代表销量或转化实证。

## 费用与证据记录

- API 返回的输入/输出 Token 仅在合法完整时记录，缺失为未知，不按字数伪造用量。
- 填写当次两项 USD/百万 Token 单价、单价来源日期、估算金额；记录服务商账单对应请求或时间范围、实际账单金额及核对差额。
- 缓存、推理 Token、平台费用和计价差异都可能使估算不同；以服务商账单为准，未知金额不等于免费。
- 界面截图应明确真实/Mock 模式、商品 ASIN、参数、版本。遮挡 Key、付款资料、邮箱、会话标识和配对信息。公开报告仅提交经审阅的匿名摘要；原始真实用户商品与未脱敏结果留在本机受忽略目录。
- 达到请求上限、预算、截止时间，或账单无法核实即停止，其余样本写「未执行」；复测需新的明确授权，保留原版本及人工修改。
