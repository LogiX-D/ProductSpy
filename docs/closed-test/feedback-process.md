# 5–10 位测试者的封闭反馈流程

**当前状态：流程已准备；尚未确认任何参与者，尚未收集反馈。** 下列 T01–T10 是可分配的匿名候选编号，不代表真人、报名、邀请已发送或测试完成。本阶段不自动发送邀请，不编造参与记录和成功率。

## 招募与最小覆盖

维护者获得测试者同意后，私下提供冻结包、校验值、[安装指南](install-guide.md)、[清单](checklist.md) 和 [反馈模板](feedback-template.md)。计划招募 5–10 位经常进行 Amazon 选品/素材采集的用户，尽量包含普通 Windows 10/11 x64、正式 Chrome 稳定版、无开发工具和高 DPI 设备。覆盖是计划，必须逐项记录实际设备，不能因为人数足够而推定覆盖完成。

联系方式和参与同意放在维护者自己的受限位置，公开仓库只用匿名编号。测试者可以退出、跳过付费 AI、拒绝提供私人商品或不回答付费意愿；不影响其他反馈计入。

## 一次实际测试如何记录

1. 记录包哈希、OS、Chrome 渠道/版本、分辨率/缩放比例和有无开发工具。先检查旧数据，停止服务并保留备份；普通测试不能随意删除本机原商品库。
2. 让测试者按指南自行取包、解压、启动、加载插件、配对、采集并保存第一个真实商品。记录实际起止时间，观察者提供帮助时记录位置及次数，不隐去操作困难。
3. 继续分组标签、组合筛选、多选、Mock、编辑历史、备份/合并恢复和停止重启。破坏性场景先用隔离样本，不能拿私人选品当可丢弃测试数据。
4. 测试者正常使用 3–7 天后填写常用功能、修改量、困难、持续使用和付费意愿。3–7 天是建议周期，实际开始/结束、退出和缺失反馈必须单独记录。
5. 维护者按 P0–P3 分级，对 P0/P1 保存证据、停止有风险路径并复现修复；复测结果与最初失败并列，不覆盖首次结果。
6. 收集完后基于真实记录汇总。公开汇总前复核脱敏和测试者同意，不上传完整用户目录、浏览器 profile、备份、配对/会话信息或模型 Key。

## 指标定义和分母

| 指标                  | 定义                                                                                      | 未完成如何处理                                                                  |
| --------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 实际参加人数          | 同意参加且开始了至少一项实际测试的人数；匿名编号只计一次                                  | 候选、邀请、报名未开始分别列出，不计参加人数                                    |
| 安装成功率            | 成功人数 / 实际尝试安装人数；成功须本机启动、正式 Chrome 插件加载、配对和工作台访问均完成 | 失败、阻断、未完成均列在分母并分别列数；下载前退出单列；仅自动化不计            |
| 首次成功采集时间 TTFC | 从测试者首次双击启动到真实商品保存到工作台且刷新仍存在的墙钟总时间                        | 未成功者无 TTFC，保留失败/退出/阻断和最后一步；暂停时长单列，不静默从总时间扣除 |
| 采集失败率            | 失败尝试 / 实际采集尝试；另列网站阻断、缺字段、保存/连接失败                              | 重试算新尝试；独立 ASIN 数单列；不可把重复尝试当更多真实商品                    |
| 最常用功能            | 测试周期内自报或人工记录次数最高的功能，注明来源                                          | 无记录为缺失，不猜为最常使用采集                                                |
| AI 人工修改量         | 按实际查看的分析分母，报告少量/多段/大部分重写的份数及原因                                | Mock 与授权真实模型分开；未看/未改/未知分别记录，不将 Mock 计入真实质量         |
| 持续使用/付费意愿     | 每题各自有回答者人数作为分母，保留全部选项和原因                                          | 未回答单列；愿意付费不是付款或商业收入，不推算全体意愿                          |

至少报告安装的成功/失败/阻断/未完成，TTFC 成功样本数、范围与中位数，真实 ASIN 数、各类失败、设备覆盖、P0/P1 状态、反馈缺失和退出数。样本 5–10 人不代表整体市场，不能用计划人数做分母。没有真实反馈时结论写「尚未收集，安装率/TTFC/意愿未计算」。

## 记录文件

[feedback.csv](feedback.csv) 只提供表头，默认没有用户行；每次真实安装尝试一行，使用 `attempt_id`，同一测试者多次尝试注明 `is_first_attempt`，汇总按匿名人去重并保留首次失败。可在受限本地复制后使用，不把填好私人信息的 CSV 提交 Git。

字段状态使用 `success / failed / blocked / incomplete / not_attempted`；时间采用含时区的 ISO 8601。`ttfc_seconds` 仅首次真实成功时填写；`ai_mode` 使用 `mock / real_authorized / unused`。逗号、引号或换行按 CSV 规则引用。缺失项留空，不能填 0 冒充零耗时/零成本。

Bug 使用 [Bug 模板](bug-template.md)，保存实际、预期和脱敏证据。保留最初版本失败与修复后通过，两者不可互相替代。关闭 Bug 需要同包哈希/修复提交、同流程复测证据。

## 公开测试决策

维护者最终根据真实设备覆盖、主要流程、数据恢复、安全和用户困难决定是否进入公开测试。存在未结 P0/P1、没有正式 Chrome 人工证据、没有普通设备安装证据或关键项阻断时，先保持封闭测试。真实 AI 未授权/未验证应明确作为限制，不宣传模型商业质量。Release 草稿保持草稿；本流程不授权公开发布或 Chrome Web Store 提交。
