## 授权后才可执行的单次流程

1. 获得明确服务商/API 地址、模型、授权 Key、本批最大请求次数、总金额上限/币种和截止时间。Key 只在本机启动器安全填写，不放进 CSV、聊天、命令参数、截图或 Git。默认模型名称不等于用户选定模型。
2. 用独立测试目录；备份本机原数据与历史，冻结当前六类真实输入。逐次记录选定市场、语言、平台、风格、时长、营销目标、自定义要求及资料缺口。不默认上传媒体。
3. 核对服务商单价和账户硬限额。建议首批最多六次、每类一次，但**建议不是授权**；不自动批量请求。请求次数、失败/超时未知账单均计入已发起次数，账单无法核对时暂停。
4. 先在 Mock 验证保存/历史/导出操作。切换真实模式后，逐次核对参数与剩余预算，在 UI 授权该次调用；记录开始/结束、模型、请求 ID 和版本。保留第一次错误，不无限手动重试。
5. 两位熟悉商品资料及目标语言的实际审阅者分别在评分表增加自己的行，独立核查原文。不能用另一个模型作为唯一事实审阅者，也不能把准备的编号计为已招募审阅者。
6. 对脚本正常朗读并按所选时长试拍可执行动作，记录实测秒数和所需道具；暂时无法试拍时标为未测。实际编辑前后分别导出版本，用计时记录人工修改，不根据文案长度估算耗时。
7. 核对服务商实际账单；明确估算/实账/未知。到达预算、次数、截止时间或出现硬失败时停止。复测需在新授权内保留原版本并追加行，不能覆盖首次结果。

## 八项质量维度与记录规则

使用 [ai-scorecard.csv](ai-scorecard.csv)。现有六行只填写公开样本来源和「未执行：缺少完整授权」；模型、当前输入、分数、Token、实际费用、朗读/试拍/编辑耗时均空白。空白代表未测，不能填 0 表示零成本或零耗时。

前七项各 1–5 分，2/4 分介于相邻等级；第八项记录费用和编辑负担的实际测量值，不给主观品质分。必须附实际原文位置与理由，不只写总分。

| 维度                   | 1 分                                     | 3 分                          | 5 分 / 测量方式                                                                                   |
| ---------------------- | ---------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------- |
| 商品事实准确性         | 编造规格、功能、效果、认证或当前变体事实 | 有遗漏/含混，需明显核查       | 关键事实可追溯、矛盾/缺口明确；页面宣称、推断与实测分开                                           |
| 营销分析具体性         | 通用品类套话或虚构演示                   | 有品类关联但角度/镜头需补充   | 基于真实资料的具体角度与至少五条不同开场，说明验证方式                                            |
| 用户画像合理性         | 无依据地断言年龄、职业、痛点或评论结论   | 画像有场景但推断/依据模糊     | 画像以假设呈现，依据与待验证方法明确；不冒称已读评论                                              |
| 视频脚本自然度         | 难以朗读、段落断裂、硬凑口号             | 五段完整但需明显口语改写      | 自然口语，Hook/Problem/Solution/Demo/CTA 连贯，实测朗读合适                                       |
| 内容可拍摄性           | 动作不可能、虚构使用结果或明显超时       | 需要较多补镜头/道具或时长调整 | 使用可取得道具，实际试拍和时长支持拍法；没有实物时不声称试拍通过                                  |
| 目标市场语言质量       | 语言错配、生硬难懂或猜当地法规           | 可理解但需明显母语编辑        | 熟悉该市场语言的审阅者认可自然表达，无无依据当地承诺                                              |
| 自定义要求遵守         | 忽略/违背要求或突破事实边界              | 仅部分满足                    | 将每条要求对应到输出，冲突明确说明，完整满足可执行要求                                            |
| 实际费用与人工修改时间 | 不适用                                   | 不适用                        | Token、已核对账单金额/币种、账单范围、修改开始/结束与有效秒数、暂停及修改比例逐项记录；未核对为空 |

事实可追溯不等于商家宣称真实有效。缺少真实评论正文时，输出不得暗示已经分析消费者评论。没有看图、视频或实际使用商品，不可写已验证性能。当前结构校验只验证契约，不保证任意模型正文不存在幻觉。

以下任意一项为硬失败，不靠总分抵消：重大虚构规格/功能/认证/功效；冒称真实评论分析；跨变体事实污染；Key 泄露或未授权传输；未授权/重复收费请求。记录 P0/P1 或内容失败证据、停止危险路径和对外使用文案。

可用「无硬失败、前七维各至少 3 分且两名真实审阅者一致认可、费用/编辑/朗读与试拍证据完整」作为首批通过规则。这个规则尚未执行，也不代表销量、转化或市场商业价值。任一维未测即保持待验收，不用平均分填补缺项。

## 费用、编辑时间与隐私

- API 合法返回的输入/输出 Token 可以记录；缺失为未知，不能按字数编造。估算需两项完整单价和来源日期，实际费用以服务商账单为准；共享账单只能明确范围，不按主观比例分摊到单个请求。
- 人工编辑从阅读原结果开始到满意版本保存结束记录墙钟时间；独立记录实际编辑活跃秒数和暂停秒数/原因。修改范围 `none / light / multiple_sections / mostly_rewritten`，只有实际检查后才能填 `none`，未编辑不等于零负担。
- 原始账单、输入快照、填写后的 CSV、模型结果和私人商品留在受限本机目录（例如被忽略的 `.test-data/phase16-ai`）。公开仅保留有同意的匿名摘要及脱敏证据，不上传 Key、Cookie、Token、配对码、付款或联系方式。
- 本表不写可用于调用的 Key，不保存完整请求头。公开截图保留版本、Mock/真实模式、公开 ASIN 和参数，遮挡身份与敏感信息。
