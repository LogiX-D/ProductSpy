# Phase 19 升级兼容验收

目标版本：v0.8.0。主要路径：冻结 v0.7.0 Windows x64 便携包 → v0.8.0 便携包。

## 当前状态

已实际执行最终 v0.8.0 Windows 便携包：v0.7.0 → v0.8.0 26项通过；v0.6.0 22项；v0.5.2/v0.5.1/v0.5.0/v0.4.0 各21项。完整证据路径及SHA见 [机器验收报告](phase19-results.json)，原始日志在 .test-data/phase19/upgrade-*.log。

## 验收方法

使用旧版便携包自带 Node.js 与真实 Next.js 服务，通过原有 API 保存合成商品，不直接写入新版 schema 来冒充旧版数据。所有数据、浏览器配置和运行时控制文件存放在新建的隔离目录；不读取默认用户商品库、真实 Key 或浏览器资料。

旧 v0.7.0 程序将实际保存：

- 原商品 ID、ASIN、时间、图片与视频 URL、商品分析及人工编辑历史。
- 分组、标签及商品关联。
- 两个商品的对比快照、Mock 对比分析和人工结论；删除其中一个源商品后继续保留独立对比。
- 用户模板的创建、编辑及恢复三份版本。
- 内容方案的 Mock 生成、人工修改、单项 Hooks 候选、同请求重放及恢复，共四份版本；保留当前版本选择、收藏和待修改状态。
- 日本市场、日文、Reels、45 秒自定义时长、内容风格、营销目标、自定义要求和追加 Prompt。
- 原配对凭据及 DPAPI 加密的合成 AI 设置。Key 是无效占位字符串，AI_MODE 固定 Mock，不产生真实模型调用。
- 通过真实旧版界面保存的分析/商品库偏好，以及独立浏览器中的内容偏好、估算单价和内置模板收藏。

升级后启动新版服务，先核对以下五个业务文件的**完整字节**不变，再通过 API 核对完整对象和 ID/版本引用：

1. `products.json`
2. `comparisons.json`
3. `templates.json`
4. `content-plans.json`
5. `analysis-usage.json`

另行检查设置文件与配对文件字节不变、原配对 Token 仍能认证。浏览器只读取已明确列出的安全偏好键；不导出 Cookie 或枚举浏览器存储。

随后在新版程序中更新原商品、生成及恢复分析、调整分组/标签、重启实际服务，核对旧模板、内容及对比快照继续保留。既有 v0.4.0、v0.5.0、v0.5.1、v0.5.2 和 v0.6.0 升级路径继续执行其适用范围；这些旧包不存在的模板/内容功能不会被虚构为旧版已有数据。

## 数据结构与回退边界

原有商品库文件版本 2，以及对比、模板、内容文件版本 1 保持兼容读取。v0.8.0 新增字段采用可选结构，不会要求清空旧数据，也不会在只读启动时重写旧文件。

历史清理后，描述性父版本关联可保存为 `archivedParentVersionId` 和 `archivedParentSha256`，原始关联保留于下载的归档。当前版本、初始恢复节点和恢复来源不会被清理。

v0.8.0 创建或编辑后的内容可能含 v0.7.0 严格 schema 尚不认识的新增字段。**正向升级通过不代表可以直接反向打开全部新版数据。** 本阶段不自动删字段、降级或清空资料。需要回退时，应先保留当前数据，使用升级前的私有数据目录副本；私有副本可能含配对和加密设置，不属于可公开分享的业务备份。

完整业务备份覆盖商品、分组标签、对比、用户模板、内容方案、相关历史与 AI 用量；普通分享备份不包含 API Key、Cookie、配对凭据或启动器私人设置。恢复采用预览、冲突保留和再次确认，不静默覆盖同 ID 的人工内容。

## 执行命令

```powershell
node scripts/test-upgrade.mjs --from artifacts/ProductSpy-0.7.0-windows-x64 --to artifacts/ProductSpy-0.8.0-windows-x64
```

要求 Windows、两个真实便携包以及空闲 3000 端口。脚本不会关闭未知监听进程。默认来源包为 v0.7.0，目标包版本从当前 `package.json` 读取。

自动化涵盖无外部 Node.js/pnpm 的启动、持久化与服务重启；鼠标双击、正式 Chrome 稳定版人工操作、Windows 原生对话框、高 DPI 和系统安全提示仍需人工验收。
