# Phase 20：候选版安全与 AI 工程检查

目标版本 **v1.0.0-rc.1**，基线 `08eefad297816b6b6b2cb236ba40ef7951960000`。范围为源码审查、隔离目录的自动化回归、故障注入及本机 HTTP Stub；不是外部渗透测试、实际断电试验或真实模型质量验收。没有执行收费 API 请求。

## 实际执行证据

执行了 13 个安全与可靠性测试文件，**188 项通过**。原始日志为 `.test-data/phase20/security-review.log`，结构化结果为 `.test-data/phase20/security-unit-report.json`。其中包含原有身份验证、HTTP、业务备份事务、历史清理、内容来源、媒体安全及 Provider 回归。

新增 `apps/web/src/lib/server/rc-ai-workflow.test.ts` 的 **3 项通过**。分别调用商品分析、竞品分析和内容生成的正式服务端路由，通过真实 HTTP 连接与当前 OpenAI-compatible Provider 通信，但目的地仅为测试进程创建的 `127.0.0.1` 随机端口 Stub。总共 6 个本机请求（3 个成功、3 个限流响应），外部模型请求与实际费用均为 0。仅使用合成商品及明确无效的占位 Key，不读取用户配置。

- 未逐次授权时返回 428；未建立用量预约、未向 Stub 发送请求。
- 授权一次后，校验真实请求路径、固定 system/user 角色、JSON Schema、模型及 Token 参数；不把 Key 或素材 URL 放入 Prompt。
- 响应结构与事实边界验证后保存结果、版本与用量；120/80 Token 配合合成定价产生 `0.00028 USD` 的**计算示例**，不代表实际消费。
- 相同 requestId 的成功重放没有第二次 HTTP 请求。
- 对三个模块分别加入人工修改，再返回 HTTP 429：人工内容、完整历史及当前记录保持不变，限流提示带安全的 Retry-After。
- 相同失败 requestId 不能再调用模型；失败状态与错误码保留。上游私密正文和占位 Key 不出现在客户端错误或用量文件。

新增 `e2e/phase20.spec.ts` 两条候选版流程检查，在生产构建的定向 E2E 中实际 **2 项通过，8.1 秒，0 跳过**，日志为 `.test-data/phase20/rc-targeted-e2e.log`，结构化结果为 `rc-targeted-e2e-report.json`。全部 E2E 的最终结果以 [Phase 20 验收报告](phase20-validation.md) 及机器日志为准，不以定向检查替代完整回归：

1. 创建商品/分组/标签、商品分析和人工修改、对比分析及人工结论、模板历史、创作参考素材、人工口播和候选生成。导出完整业务 JSON 后真实删除自有商品及各模块记录；恢复时拒绝过期预览，重新预览后保留本机较新商品，恢复原 ID、ASIN、快照、素材来源、所有历史和用量。恢复后的 requestId 重放仍不新增生成；实际 UI 导出的文本 ZIP 验证 CRC、来源、人工内容及无媒体文件。
2. 非法版本、未知私密字段、异常内容快照、跨站来源及匿名访问被拒绝；每次操作后核对全部业务对象没有改变。

首次完整 E2E 中，第 2 条的匿名访问断言实际失败（期望 401，收到 200），没有隐藏该结果。保留的 Trace 证实该请求携带 Cookie；检查当前 Playwright 1.64 的 `runBeforeCreateRequestContext` 实现及共享 `storageState` Fixture 后，确认新建请求上下文默认继承了测试工作台会话，测试当时并非匿名。这属于新增测试的隔离错误，不能记成生产 API 绕过身份验证。修复为显式空 `storageState`，增加请求前后的 Cookie 为空断言，保留三个接口必须返回 401 的原断言；修复后定向 E2E 通过。完整 E2E 结果由最终验收报告及原始日志记录。

这些流程使用合成 Fixture 与明确标记的 Mock，不能冒充真实 Amazon 采集或真实 AI 内容质量。

## 保留的安全边界

| 检查项         | 核查结果及自动化证据                                                                                                                                | 仍存在的实际边界                                                     |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 本机服务       | loopback 绑定、Host/Origin/Sec-Fetch 校验、HttpOnly/SameSite=Strict 会话；备份、历史、模板和内容接口 web-only，匿名与跨站访问拒绝                   | 已控制当前 OS 用户的进程不属于应用身份验证能够抵御的威胁             |
| Chrome 配对    | 120 秒一次性配对码、绑定扩展 Origin、服务端哈希令牌、重新配对和撤销；身份验证回归保留                                                               | 原 55×58 小空白窗口尚无真实根因证据，继续人工待验收                  |
| MV3 权限       | 保留 activeTab/scripting/storage 与固定 localhost host；没有增加广泛 Amazon 权限或远程代码                                                          | 正式 Chrome 稳定版手工安装与系统窗口验收独立记录                     |
| Key 管理       | Provider 仅服务端读取；Windows CurrentUser DPAPI 配置。普通业务备份不包含 Windows 设置、配对、会话和环境文件                                        | 商品业务文件没有应用级加密；完整用户目录不能作为可公开分享的业务备份 |
| AI 调用        | HTTPS 远程地址、仅明确 loopback 可用 HTTP；拒绝带凭据/查询/片段的地址；拒绝重定向、2 MiB 响应限制、请求及流式读取超时、清晰失败提示、无收费自动重试 | 超时不证明平台未计费；先查结果和服务商账单，再手动决定新请求         |
| 授权与幂等     | 三条正式路由 Stub 验证逐次授权、持久化 requestId/指纹、成功重放、失败不自动重发；保留并发与日限额                                                   | 没有授权 Key、模型、次数和预算，真实模型质量仍未验收                 |
| Prompt/事实    | 网页和模板放入不可信资料，固定系统规则，不提供执行工具；变量白名单不执行表达式/递归；保存的分析与竞品结论保留来源和未验证分类                       | 结构与分类验证不能证明生成的所有自然语言事实正确；需要人工核实       |
| 媒体与 SSRF    | HTTPS Amazon CDN 白名单、私网/恶意域名拒绝、无认证或 Cookie、禁止重定向、MIME/文件签名/大小校验；HLS 不伪装成可直接下载文件                         | 实际视频归属/播放还需人工观看，不绕过 DRM、登录、验证码或地区限制    |
| 导入/导出      | JSON 严格 schema、版本、数量、大小、关联 ID、快照来源及安全 URL 验证；CSV 公式转义；ZIP 固定文件名、CRC 和路径检查；没有任意 ZIP 解压导入           | 普通业务备份不扫描用户自行写入的文案，分享前仍需检查内容             |
| 完整业务恢复   | 五文件独占事务、staging/prepared/committed 日志、原始字节哈希与安全原子写入；CAS 预览和二次确认；保留本机人工内容，部分失败回滚，读取前恢复         | 故障注入是实际文件操作，但不是物理断电或磁盘损坏验收                 |
| 路径及损坏保护 | 恢复暂存目录拒绝 junction/symlink、未知文件和坏日志；原始文件保留并阻断，不能访问外部目标；并发恢复与账本写入不丢 ID                                | 同 OS 用户外部程序持续篡改文件仍需操作系统层防护                     |
| 用量及历史恢复 | 旧备份不能重置既有预约、指纹、状态和本日限额；历史清理需要绑定实体/版本/摘要/更新时间的限时归档凭证及用户确认，保护当前与恢复节点                   | 不自动删除人工编辑；历史归档是人工恢复参考，不静默覆盖同 ID 记录     |

本次安全审查没有复现新的生产安全缺陷，因此没有为完成阶段而制造缺陷或无依据地更改安全策略。Phase 19 已修复的恢复事务、锁模式、数据来源与归档边界继续由原有严格断言验证。

## 发布条件

发行包的 ZIP 完整性、哈希、路径、权限及敏感文件检查由最终候选产物执行，具体结果见最终机器验收报告；本文件不将源码检查冒充发行包验收。正式 Chrome/Windows GUI、高 DPI、SmartScreen、原生目录操作、原配对小窗口与真实模型质量必须分别保留真实证据或人工待验收状态。

**功能完成、工程自动化通过、真实环境通过与可以公开发布是四种不同状态。** 本报告只支持已经执行的工程安全检查，不构成公开发布授权。
