# Phase 21：三个正式 AI 功能的真实模型验收准备

准备日期：2026-10-14（Asia/Shanghai），候选版 v1.0.0-rc.1。**这是可执行的准备材料，不是真实 AI 质量报告。** 尚未获得 Key、确切模型、最大请求次数和金额预算的完整授权，本阶段未发起外部模型请求；评分、实际费用及人工修改时间均未测量。没有读取维护者的受保护 AI 设置或私人商品库。

## 已核查的实现与边界

只读核查了三个正式路由 `analyze-product`、`analyze-comparison`、`generate-content`，共用的 OpenAI-compatible Provider 和用量账本，以及 Phase 20/19 实页报告、Phase 16 准备记录。三个路由在真实模式下均要求 Web 身份及本次 `authorizeReal`；先预约本机用量再请求服务。已有请求编号回放保存结果或拒绝重复发起，不自动重试超时、429、参数错误或结构不符的请求。远程地址要求 HTTPS，本机 HTTP Stub 不是真实服务商验收。

Provider 的默认超时为 60 秒、硬上限 120 秒，响应最多 2 MiB；默认每日 UTC 50 次真实请求、真实并发最多 2。它们是工程保护，**不是本批授权或金额硬预算**。输出 Token 限制也不等于美元上限。超时、取消或失败可能已计费，应计入已发起次数并核查服务商账单。不同请求编号的人工重试仍可能再次计费。

商品页面和模板文字是待核实数据，不能提升为系统指令。现有三个功能默认不发送图片、视频文件或专门的媒体 URL 字段；不得据此声称模型已看过媒体或实测商品。评分与评论数量不是评论正文，六个样本都没有采集评论正文。商品原分析和竞品结论如果用于创作，必须以其带日期、版本、来源的推断资料使用，不能转成已验证事实。

Phase 20 的 Mock 完整链路和本机 Stub 契约，只证明当时的工程行为。Phase 21 自动化结果另见本阶段主报告，不能把旧数量或任何 Mock 文案评分写成真实模型质量。

## 授权前的本机准备

1. 使用独立测试目录，先退出现有 ProductSpy，并通过启动器既有 `-DataRoot` / `-RuntimeRoot` 测试参数启动隔离实例；路径和操作见 [维护者验收清单](manual-acceptance.md)。AI 设置位于所选 DataRoot 的 `settings` 子目录，不读取生产配置。不得用生产商品库做删除、恢复或错误注入。
2. 正常打开六类页面重新采集；核对当前 ASIN、变体、标题、价格币种及商家原文。遇访问限制记为受限并停止，不绕过、不通过反复重试挑成功。若只评价已保存的历史快照，须由维护者明确接受其日期和缺口，不把它写成当前页面。
3. 冻结输入 JSON、版本、采集时间、参数、模板及引用结论，并保存 SHA-256。历史原始 capture 可用于核对，但不把浏览器 profile、Cookie 或整个原始 HTML 发给模型。
4. 在 [ai-authorization.template.json](ai-authorization.template.json)的**受限本机副本**填写服务商、HTTPS API 地址、确切模型、授权功能、最大总请求次数、总预算/币种及截止时间。模板不读取配置、不触发请求、不存 Key；Key 仅在本机启动器安全设置。表内 `approved: false` 和空额度保持未授权，建议数字也不代表授权。
5. 在服务商账户设置可验证的测试消费硬限额；如服务商不提供硬限额，只能在维护者明确接受残余风险并给出保守预算后逐次人工执行。事前核对输入、输出及其他收费项和日期；本机估价与账单分列，不宣称估算一定覆盖实际费用。

## 三个正式功能的逐次测试

[ai-scorecard.csv](ai-scorecard.csv)包含六类 × 三个功能共 18 行空白记录。它们是预备任务，不是 18 次调用授权；没有执行的分数、Token、费用和耗时留空，不能用 0 冒充零成本或零编辑负担。

- **商品分析**：逐类选择真实冻结商品，检查事实依据、商家宣称、用户画像假设和未知项；核对至少五条不同开场及完整脚本。保存输出与生成参数，人工修改另存历史，再检查重新生成未覆盖人工版。
- **竞品对比**：每类先正常采集至少另一个可比较且不同 ASIN 的同品类公开商品，冻结 2–5 个来源。本目录只有每类一个主样本，**第二商品与竞品输入仍待准备**；不得以同一 ASIN 的不同站点冒充两个独立竞品，也不把相框与保湿霜的跨品类表当作商业竞品质量。不同币种不判断价格高低，没有真实评论正文不做评论主题分析。记录所有快照与对比方案版本。
- **内容创作**：选择冻结商品、模板版本和参数；如引用分析/竞品结论，记录其 ID、版本、时间与推断属性。核对卖点文案、五条开场、五段脚本、分镜、口播、标题说明和提示词；人工采用版与重新生成候选版分别保存，导出并核对来源说明。

每次调用前重新核对模型、模式、当前累计次数与剩余预算，使用 UI 的「授权本次调用」。默认逐个执行，不批量授权、不无限重试、不切换参数试探兼容性。一次请求失败、超时或结果未落盘也计入本批已发起次数，先看本机账本和服务商账单；未知金额暂停后续请求。重新请求必须仍在明确授权范围内，保留首次失败，不能通过新请求编号掩盖重复费用。

各类至少为中文、英文、日文之一设置明确目标市场、平台、风格、15/30/60 秒和可核对的自定义要求；分配在授权前写入评分行，不根据结果倒改要求。可在六个主样本之间分配不同语言，不能把三个语言轮次默认为已授权。内容创作支持的自定义秒数也需单独记录。

## 评分与阻断规则

事实准确、营销具体、画像合理、语言自然、可拍摄、市场语言及自定义要求遵守各按 1–5 分，附输出原文位置、来源字段和理由。1 分代表重大问题，3 分代表可用但需明显修改，5 分需来源明确、自然表达且具备相应人工证据；2/4 分处于相邻等级。商品分析和竞品输出中的拍摄建议同样可评估，未含视频内容或未试拍时明确填待验收，不凭文本长度填实际时长。

由实际熟悉商品资料和目标语言的审阅者独立核验；不得虚构评审者或把另一个模型打分当唯一证据。朗读和试拍分别计时，记录道具、镜头与不可执行动作；修改时记录实际开始、结束、活跃编辑秒数、暂停秒数/原因及修改范围。费用以服务商账单为准，记录 Token、已知估价、实际金额、币种、核对时间与账单范围；没有单请求账单就标明不可分摊，不猜费用。

重大虚构规格/认证/功效、冒称真实评论分析、跨变体污染、Key 泄露、未授权传输或重复付费属于硬失败，不能靠平均分抵消。此时停止危险路径并创建带证据的缺陷；处理后复测追加新行，不覆盖首次结果。可以把「无硬失败、各已测维度至少 3 分、两位实际审阅者一致认可且费用/编辑/朗读/试拍证据完整」作为首批候选通过标准；任一必要项未测仍是待验收，不能据此保证销量或商业收益。

填写后的评分、授权副本、原始模型输出、输入快照和账单留在受限本机目录。公开报告仅提交脱敏摘要和经同意证据，不上传 Key、Cookie、Token、配对码、付款资料、联系方式或私人商品库。
