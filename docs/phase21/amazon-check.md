- 8 个成功主页面中，ASIN、标题、主图、图库、高清来源、评分、评论数量和主图 HTTP 检查均为 8/8；价格及货币为 6/8，其余两页未知；品牌和卖点各 7/8，缺失各一项。没有用推荐区价格或站点国家猜测缺失值。日本页实际显示 TWD，按页面记录。

## 两处视频差异的核查

`CeraVe B00TTD9BRC` 与 `OXO B0000CCY1E` 实页采集 `videos=[]`，稍后 HTML 中各有一个绑定当前 ASIN 的公开 MP4 地址。独立审计保留原 `videos=fail`，没有把失败改成通过。

已实际执行离线探针：[video-timing-probe.json](video-timing-probe.json)。使用原冻结包 `content.js`，在只允许执行本地扩展脚本的 JSDOM 中读取保留 HTML；也用当前源码解析同一 HTML。两者均各提取出一个视频，URL 哈希和绑定关系保留。书籍对照样本两者均得到原有的 MP4/HLS 两项。没有执行 Amazon 的页面脚本或重新访问页面，也没有下载视频。

原采集顺序是：观察 DOM → 扩展采集 → 立即重复采集 → 主图请求及视频 HEAD（如果有）→ 保存 HTML → 截图。**采集瞬间的 a-state 没有单独冻结。** 因此，当前证据支持“采集结果与稍后 HTML 不一致”和“冻结解析器能够解析该静态数据”；不能证明当时数据已经存在，更不能断言异步加载是唯一根因或已修复。这是待定位的采集质量问题，保留发布风险，不为消除审计失败增加宽泛扫描或放松 ASIN 绑定。

维护者按 [人工单 A01/A03 与 C07](manual-acceptance.md)在正式 Chrome 中核对页面视频可见时间、当前 ASIN、首次采集、等待页面完成后的手动重新采集，以及每次截图时间；有条件时在测试环境分别保存采集前后 a-state 和结果，记录 MP4/HLS 类型与原始链接。公开材料只保留 URL 哈希，不能上传浏览器身份或签名凭据。视频归属与实际播放必须独立验证；受保护资源不绕过限制。
