# Phase 21：证据、脱敏和结果填写规则

适用于冻结的 ProductSpy 1.0.0-rc.1。此文件定义维护者如何提供真实证据，不是验收通过声明。2026-10-14（Asia/Shanghai）准备；未执行结果保留 `pending`。

## 结果状态

| 值               | 使用条件                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| `pending`        | 尚未操作，或尚无本轮可核查证据。空单元格不是通过。                                                         |
| `passed`         | 对应的完整动作已执行，预期满足，已填时间/环境/证据。不能凭相似自动化或上阶段结果填写。                     |
| `failed`         | 真实执行复现不符合预期；需缺陷编号、步骤、实际/预期和脱敏证据。                                            |
| `blocked`        | 试图执行但受环境、权限、访问限制或明确策略阻断；写清阻断原文与继续条件。不是产品缺陷或成功。               |
| `not-reproduced` | 在记录的准确条件下执行了故障复现步骤而未重现。不能等同于根因已修复。                                       |
| `not-applicable` | 已确认该次样本确无适用资源或条件，例如商品没有公开直接视频；写依据，不能用来掩盖必需的正式 Chrome/DPI 项。 |

同一项在多个设备/缩放/版本上执行应新增行，不覆盖原失败记录。复测列出关联缺陷和前次证据。人工和自动化分别统计：不能把 711 单测或 CFT 通过行加到正式 Chrome 人工分母。没有实际测试人数就不报告用户成功率。

## 必需的环境元数据

每个执行会话记录一次，结果行引用 session_id：

```text
session_id: P21-YYYYMMDD-设备代号-序号
performed_at: ISO 8601 时间（含 +08:00 或实际时区）
tester_alias: 自选代号，不要求真名
source_commit: 本轮实际核对的 main SHA
candidate_version: 1.0.0-rc.1
windows_zip_sha256: 原始下载 ZIP 的 SHA-256
extension_zip_sha256: 同版原始扩展 ZIP 的 SHA-256
package_source: 维护者私下原包或有权限访问的 Release 草稿
windows_edition_build_architecture: 真实 Windows 产品名、OS build、x64
account_type: 标准用户/管理员（是否实际提权另记）
isolated_data_confirmed: 专用 Windows 测试账户/维护者限定目录；不得写私人路径
chrome_product_version: 正式 Chrome 的产品名与完整版本
chrome_channel_and_source: 稳定渠道/未知，以及官方安装或组织管理来源
extension_id: 公开扩展标识，不含配对令牌
display_resolution: 物理显示器分辨率
windows_scale_percent: 125/150/200 或实际值
chrome_page_zoom_percent: 页面缩放，和 Windows 缩放分开
window_state_and_bounds: 是否最大化、外边界像素尺寸
viewport_and_device_pixel_ratio: 可选，仅为 CSS 像素与比例，不代替物理 DPI
ai_mode: mock；真实测试必须另有授权记录
```

不要提交完整 `chrome://version`/`chrome://policy`、应用库存、命令行、profile 路径或 Windows 用户信息。只摘录必要、已脱敏字段。CFT 明确标 `Chrome for Testing`；Edge 不记为正式 Chrome 验收。

## 每项证据最小集合

1. 案例编号、环境会话编号、时间、操作者代号、实际步骤、预期与实际结果。
2. 实际使用的原包哈希与对应版本。源代码最新不代表已装包最新；同版本不能换包不换哈希。若需要修复构建新 RC，重新列明测试覆盖。
3. 截图保留原生窗口完整边界和关键提示，注明缩放条件；不要用浏览器 viewport、拼贴、生成图或拉伸截图替代真实桌面。可提供短录像说明双击/关闭/重连顺序。
4. 文件操作结果提供文件名、字节数、可选 SHA-256 和脱敏打开截图；“点过导出”不等于文件成功保存。ZIP 实际解压核对目录/内容；图片或视频 URL 解析成功不等于播放或下载成功。
5. 数据完整性只提交自建 P21 资料的 ID/ASIN、计数、快照/版本关联和人工标记核对结果；业务 JSON 原件在维护者本机保存。公开可见 ASIN/URL也先确认不涉及私人选品。

建议命名 `P21-YYYYMMDD-caseID-device-scale-step.png` 或 `.mp4`。证据文件哈希针对**最终脱敏公开副本**计算；私密原始记录另行保留，不上传仓库。不对拍摄前未显示的操作做成功推断。

## 配对小窗口专属记录

使用 [操作单 C07](manual-acceptance.md) 的完整步骤。至少包含：发生入口、打开前/打开后窗口、窗口标题/外边界与内容区域尺寸、正式 Chrome 版本与来源、系统缩放、页面缩放、分辨率、最大化状态、DPR（如读取）、复现频次和逐步截图。原先约 55×58 图仅为历史症状，不自动构成本轮复现。若设备库存没有稳定版或桌面操作被拒绝，应保留阻断原文，不改用 CFT 后标通过。

## 备份与恢复专属记录

按 [操作单 B01–B09](manual-acceptance.md) 分别保留：

- 导出前各实体及历史计数、实际备份文件 SHA、schema/数量/引用核对。
- 预览与取消、同 ASIN/同 ID 冲突、保留较新人工内容的实际结果。
- 删除目标只属于隔离 P21 账户的确认记录；不能记录生产资料的破坏性测试。
- 恢复结果成功/跳过/失败数量、原 ID/ASIN/分组标签/历史/快照/参考素材/用量对应、停止重启后的核对。
- 故障注入的确切点与自动化日志；人工无法安全做则待验收，实际文件故障注入也不能称物理断电验收。

普通业务备份排除 API Key、Cookie、配对凭据和 Windows 加密设置。完整用户目录和日志可能敏感，不能作为可分享业务备份提交；恢复依赖资料时由维护者在本机脱敏后摘取最小证据。

## 脱敏规则

不可公开 API Key、Authorization、Cookie、令牌、会话编号、配对码、DPAPI 密文文件、浏览器资料目录、完整用户目录、私人商品库、家庭地址/配送信息、邮箱及个人账户名。配对码可见的窗口先遮挡码，再保存公开副本；令牌不得出现在控制台或网络面板截图。截图不得展示真实 AI Key，即使仅为一次测试。

证据要忠实：允许隐私遮挡和注明裁切，不能删除错误状态、替换内容或把 Mock 改成真实 AI。敏感原日志不上传；仅提供错误原文/时间/请求 ID（确认不是认证凭据）等最小可诊断字段。Key 仅由维护者在本机启动器填入，不能发在表格、聊天、Issue、Git 或本目录。
