本单验证冻结的 **ProductSpy 1.0.0-rc.1**。编写日期为 2026-10-14（Asia/Shanghai）。源码基线 `bcf049d45e65ea6da798b53aa6b57b20508927f9`；当前远程、原包和哈希由本轮基线审计核对。本单是可执行步骤，**不代表已经人工通过**。逐项结果填入 [manual-results.csv](manual-results.csv)，证据要求见 [evidence-requirements.md](evidence-requirements.md)。

Phase 20 的 711 项单测、33 项 E2E、便携和升级记录属于历史自动化证据，不复制成人工成绩。本轮自动化和桌面实际证据以本轮验收报告为准。Chrome for Testing（CFT）、Playwright viewport、无界面启动分别不能替代正式 Chrome、Windows 显示缩放或原生窗口操作。

## 开始前：用独立资料完成测试

### 普通维护者推荐方式

1. 使用一台自有测试电脑，或一个**专用于验收的标准 Windows 用户账户**。账户应没有既有 ProductSpy 商品库或 AI Key；由设备所有者按 Windows 正常方式准备，不需要为运行 ProductSpy 提权。若没有隔离环境，暂停删除、恢复、配置及异常测试，保留 `pending`。
2. 在这个账户中打开文件资源管理器，在地址栏输入 `%LOCALAPPDATA%`，确认尚无 `ProductSpy` 目录。若已存在，停止并让维护者确认用途；不要删目录、改名、覆盖或清空来“准备环境”。
3. 确认其他账户、开发服务和工作台已正常停止。端口 3000 是整台电脑共享资源，切换 Windows 用户不自动停止旧服务。不要结束不认识的进程。
4. 获取维护者提供的原始候选 ZIP、扩展 ZIP、`SHA256SUMS.txt`；先核对文件名和本轮冻结哈希。不会核对时请维护者协助，不要求安装 Node.js/pnpm。不要用源码 ZIP 代替便携包。
5. 在测试账户的「文档」中新建 `ProductSpy-Phase21` 文件夹，完整解压包到其中。另建 `证据`、`成果`、`素材` 文件夹；路径由自己明确选择，不使用系统或生产数据目录。
6. 正式 Chrome 使用一个专用的、不登录同步的测试 profile；不要导入私人浏览器资料。打开 `chrome://version`，记录产品名和完整版本，记录安装来源及更新渠道。不要提交整个页面截图中可能包含的用户名或 profile 路径。

**只有新解压目录、Chrome 新 profile 或无痕窗口都不能隔离工作台资料。** `ProductSpy.cmd` 默认仍使用当前 Windows 用户的 `%LOCALAPPDATA%\ProductSpy`，不会因解压目录改变而换库。本单不要求普通用户执行修改环境变量、权限或生产路径的命令。高级隔离启动必须由维护者明确准备，同时隔离 DataRoot 与 RuntimeRoot，并确认只操作自己的服务；不能当作默认 CMD 双击验收。

本轮统一使用 `P21-日期-用途` 命名分组、标签、模板、对比和内容方案。仅采集公开、非私人选品的真实商品。记录证据只包含必要 ID/ASIN、公开来源和脱敏截图，不包含完整用户目录。

### Windows 显示缩放矩阵

W13/W14/W15 分别对应 **125% / 150% / 200%**。优先在已具有对应显示缩放的自有设备执行；若需调整，必须由设备所有者自行在 Windows「设置 → 系统 → 屏幕」选择受支持值，并记录原值、按系统要求重新登录/启动，测试后由所有者恢复。自动化不得擅自修改系统设置。没有该显示条件保留待验收，不用浏览器缩放或截图拉伸代替。

每个缩放值检查：启动器状态与所有按钮、AI 配置窗口全部字段/保存/取消、正式 Chrome 工具栏 Popup、工作台「安装与配对」、素材原生目录窗口。记录物理分辨率、Windows 缩放、Chrome 页面缩放和窗口是否最大化；检查文字截断、按钮遮挡、垂直滚动、Tab/Shift+Tab、Enter/Escape。截图保留窗口完整边界。重新启动后仍无法看到保存/退出按钮即记实际缺陷，而非直接调回 100% 后写通过。

### 配对 55×58 小空白窗口专项（C07）

1. 记录原操作入口：工作台「安装与配对」、Chrome 工具栏扩展、Chrome 新开窗口，还是其他系统窗口；不能将三者混称 Popup。
2. 在首次生成码之前截取整个应用窗口及弹层；记录打开前后操作顺序、是否默认浏览器非 Chrome、是否使用其他浏览器、是否有阻止弹窗提示、是否新建浏览器窗口及其标题。
3. 记录正式 Chrome 完整版本/渠道/来源、Windows build、显示器分辨率、系统缩放、浏览器页面缩放、窗口最大化状态。维护者可在不带敏感信息的新标签读 `window.innerWidth/innerHeight`、`window.outerWidth/outerHeight`、`devicePixelRatio` 作为补充；这些值不是物理 DPI 测量。
4. 同一环境依次执行“首次打开 → 关闭 → 再打开 → 生成码 → 关闭 → 再打开”，每步记录实际窗口外边界/弹层内容区域像素尺寸及截图。若出现原图约 55×58 小框，保留未放大的原截图和动作前后录像；不要只截内部空白。
5. 页面码可见时只保留遮挡后的公开副本。不要记录连接请求头、Cookie、令牌或含码的网络请求内容。需要私下检查控制台时先复制无秘密的错误原文。
6. 无法复现填 `not-reproduced` 并附本次条件；受工具/设备限制填 `blocked` 或 `pending`。只有复现、定位具体根因、有修复后同条件复测及回归证据，才能在缺陷表写“已修复”。Phase 19/20 的页面弹层尺寸断言不替代这一项。

## D. 完整业务备份 → 删除自建资料 → 安全恢复

**此节只允许专用空白测试账户。** 若看到私人商品、未知方案或已有 Key，立即停止，不做删除。不需要直接修改或删除 data 内 JSON。

1. **B01 导出**：在「设置与备份」记录当前商品/分组标签/对比/用户模板/内容/历史/用量数量。明确选择是否附带此浏览器偏好，点击「导出完整业务备份」，保存到“成果”。另外备份已下载素材。
2. **B02 核对**：确认 JSON 文件已真实写入磁盘，用记事本只读查看 format、schemaVersion、五类业务内容及 P21 人工标记。核对商品 ID/ASIN、对比及内容快照、模板版本、所有历史、参考素材来源和用量；不自行编辑。它不含 Key/Cookie/配对/Windows 加密设置/未保存草稿/媒体文件。完整目录副本是私人资料，不提交作公开证据。
3. **B03 取消预览**：「选择备份并预览恢复」，核对数量、重复冲突、未知引用和容量；取消，刷新证实没有写入。保留文件原件。
4. **B04 冲突保护**：先把一个已保存人工标记改为 `P21-较新人工内容-保留`，再预览旧备份；按界面安全策略恢复并二次确认。现有资料优先保留，不得覆盖新人工内容。记录冲突及成功/跳过/失败数。
5. **B05 删除自建资料**：再导出一份含最新人工内容的完整备份并核对，之后只通过各模块 UI 删除带 P21 标记的测试商品、对比、用户模板和内容方案，每次核对名称和选择数量并确认。先观察删除商品后对比/内容快照保留，再删除独立方案。仅在测试账户无其他资料的前提下整理其测试分组标签；内置模板与用量不要求删除，不修改用量账本。
6. **B06 恢复**：选择最新备份并预览，确认增加数量、冲突和保留策略。恢复浏览器偏好需另外明确勾选；确认一次后等待结果，网络中断先刷新核对，不盲目重复提交。
7. **B07 一致性**：逐项与资料核对表对照原商品 ID/ASIN、分组标签、对比成员快照、商品分析人工标记与历史、模板 ID/历史、内容 ID/当前人工版本/完整历史/参考素材、用量记录。恢复不自动重新发出 AI 请求。重新导出与原备份比较时忽略 exportedAt 等导出时间字段，不能把整个 JSON 字节不同直接判为数据丢失。
8. **B08 重复及重启**：重复预览同一份备份应显示冲突且保持现有资料；停止、重启，复核结果及配对。导出一份最终备份，留作后续升级测试。

**B09 部分失败与异常退出**：通过本轮实际文件故障注入、事务恢复及升级自动化报告核对；人工普通操作无法安全制造时保留人工待验收。不要在写入中拔电、拔盘、杀未知进程、截断 JSON、删 `.workspace-restore` 或改权限来“测试”。在维护者专用故障环境中可执行时，必须先有完整回退副本、限定进程/目录、记录故障点、失败提示、原文件哈希和恢复后核对；这仍不等于物理断电验收。
