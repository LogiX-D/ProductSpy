# SaaS 审核步骤草案

尚无获准部署的审核环境或专用账号。此文件不包含凭据，不证明已向 Chrome Web Store 提交。未来所需专用测试账号通过官方测试说明入口私下提供；不要写入仓库、PR、截图或知识库。

1. 核对待审 ZIP 的 SaaS origin、版本、checksum 与当前来源记录；manifest 在 ZIP 根目录，权限与当前 SaaS 披露一致。实际安装后记录 Chrome 稳定版版本和扩展 ID。
2. 打开获授权的 HTTPS 工作台，使用专用审核账号登录。普通用户不安装 Windows 工作台、Node 或数据库。
3. 打开扩展，点击网页登录与授权，在工作台核对扩展 ID 并生成一次性授权码，粘贴到扩展完成账号连接。记录失败/过期/错误 ID 的拒绝结果，截图避开码和 token。
4. 打开实际 Amazon 商品详情页。点击扩展，先阅读并同意数据采集用途，再采集并保存。核对 ASIN、标题、字段缺失、媒体与当前账号一致；不要用 fixture 或修改页面 DOM 代替实页。
5. 在 SaaS 商品库确认上传记录，重复保存核对不产生重复商品。断网保存后恢复网络，确认队列和错误状态恢复；退出/换账号时原账号待同步资料不流入新账号。
6. 在工作台确认 AI 模式与额度，按单独授权预算执行真实分析并保存，随后从另一物理设备登录查看。Mock、本机另一浏览器和自动化截图分别标记，不能替代真实 AI 或跨设备证据。
7. 使用另一受限账号核对商品、历史与任务不可访问；检查 Free / Pro、用量上限及失败任务。付款验收使用获准的 Stripe test 环境，另行记录真实交易授权和结果。
8. 核对隐私链接、联系人、数据保留/删除与实际行为一致，截图来源与同一次 SaaS 构建绑定；记录原生弹窗、窄屏页面和实际业务结果。

只有上述实际结果和公开资料完整后，发布者才可在单独授权范围内准备提交。官方 [发布流程](https://developer.chrome.com/docs/webstore/publish)区分 ZIP 上传、隐私/测试资料、提交审核和发布；本地生成 ZIP 不执行任何这些远端操作。
