# Chrome Web Store 审核复现说明

对应版本：ProductSpy 1.0.0（Manifest 数字版 1.0.0.3）。本文件仍为未提交的商店审核草案。扩展是 Amazon 商品采集工具，依赖用户自己运行的本机 Windows 工作台。没有审核账号、Amazon 账号要求、支付墙或 API Key 要求。默认 Mock 模式能完整展示分析流程；真实 Amazon 可能出现地区/验证码限制，遇到限制应停止并记录，不绕过。维护者声明及证据边界见[最终归档](../v1.0.0-final-manual-acceptance-results.md)。

## 发布者提交前应补全

- 扩展包：`ProductSpy-1.0.0-extension.zip`，ZIP 根目录为 `manifest.json`。
- Windows 工作台包：`ProductSpy-1.0.0-windows-x64.zip`。
- **便携包精确公开下载地址：提交前填写。** 仓库源代码地址不能替代可直接运行的下载资产。
- 发布版本、包 SHA-256、Windows / Chrome 稳定版验收记录：见本次发布的验收报告和校验文件。
- 联系与支持：[ProductSpy Issues](https://github.com/LogiX-D/ProductSpy/issues)。

以上下载地址未填写或审核环境无法运行本机 Windows 程序时，完整业务无法复现，应视作提交阻塞。不要填写虚构账号、预置令牌或 API Key 来绕过配对。

## 审核步骤

1. 在 Windows x64 解压工作台便携包，双击 `ProductSpy.cmd`。它使用包内运行时启动本机服务，并打开 `http://127.0.0.1:3000`；无需自行安装 Node.js 或 pnpm，不需要管理员权限。
2. 保持 ProductSpy 启动窗口运行。若 3000 端口由其他程序占用，启动器会明确提示，需先关闭占用程序；不会悄悄使用其他端口。
3. 安装本次审核扩展。若进行提交前本地复现，可在 `chrome://extensions` 开启开发者模式并加载便携包中的 `extension` 目录；正式商店安装后的扩展 ID 可能不同，仍需按下一步正常配对。
4. 工作台点击「安装 Chrome 扩展」或右上角扩展说明按钮，生成配对码。配对码 2 分钟后失效，只能使用一次。
5. 打开 ProductSpy Popup，将码填到「工作台配对码」，点击「连接工作台」，确认显示「工作台已连接」。配对不依赖当前标签是否为商品页。
6. 正常打开公开 Amazon 商品详情页，例如 `https://www.amazon.com/dp/B00TTD9BRC`。等待页面加载完成，点击扩展；首次使用先阅读说明并点击「同意并开始采集」，然后应显示当前 ASIN、标题、主图和可取得字段。价格、视频受地区和页面数据可用性影响，空字段不是模拟值。
7. 点击「保存到素材库」，在工作台商品库打开该商品，再点击「开始 AI 分析」。默认 Mock 返回标注为演示的完整分析、至少 5 条 Hook、五段脚本和 Prompt。
8. 关闭并再次打开浏览器页面，已保存商品和分析仍在。再次采集相同 ASIN 会更新原记录，不新增重复商品。
9. 使用启动器停止工作台，再在扩展点击保存。应提示工作台未连接并保留待同步商品。重新启动工作台后点击「重试同步」，商品恢复同步。
10. 工作台中的「撤销扩展连接」使旧令牌失效；重配后可恢复同步，不清空商品库。新码过期时重新生成。
11. 退出并重启便携工作台，原数据目录保持不变。将同版本或新版程序解压到另一目录，也不应覆盖用户数据；详情见 Windows 指南中的更新步骤。

遇到 Amazon CAPTCHA、登录限制或地区不可达时，记录无法验收，改用正常可公开访问的商品页；不绕过验证。可先验证安装、配对、空库和 Mock 提示，不能将这些检查替代真实 Amazon 采集验收。

## 边界说明

- 当前仅 Windows x64 便携工作台；没有云端免安装替代环境。
- 本机服务只监听 loopback，商品、配对和 AI 业务 API 都要求会话或令牌认证。
- 扩展代码全部在包中。Amazon JSON 数据、图片、视频和 AI 响应不是远程可执行代码。
- 真实 AI 可选，审核不需要配置；未配置时有完整 Mock 演示。Mock 的输出不用于宣称真实模型效果。
- 商品和配置位于独立用户数据目录，卸载扩展不会删除已同步的工作台文件。清理数据需用户主动执行。
