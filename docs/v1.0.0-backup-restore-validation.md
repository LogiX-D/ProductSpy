## 真实文件锁失败、回滚与重启

1. 仅锁隔离目标 `templates.json`，使用有 15 秒看门狗的自有 Windows 文件句柄，允许读但阻止替换。
2. 在冻结服务上真实提交恢复；返回 **500**，清楚提示“恢复未能确认完成…原始资料或恢复日志已保留…不会自动重复恢复”。实际观察到 `products.json` 已发布；没有虚构其他文件也已发布。
3. 保留 `prepared` 事务日志，核对五份 old 和五份 new 的哈希。锁仍在时业务读取返回 **500** 并保留日志，**没有返回半恢复的业务状态**。
4. 释放自有锁后，下一次正常读取触发恢复；五个原业务文件均逐字节回滚，验证后才清理事务目录。
5. 用户等价的明确新预览、确认、重试仅导入 1 个新合成商品，原 2 商品和较新人工内容完整保留；不自动重试。
6. 正常停服后，另行在已停止的隔离目录构造有效 `prepared` 日志及部分发布状态；启动原便携包后正常读取安全回滚，五文件 SHA 和最终业务对象一致。

第 6 项是**停机后合成的中断状态**，不是实际中途杀进程、断电或磁盘故障。没有验证真实满盘、坏盘、杀毒隔离、网络/可移除文件系统或任意日志损坏。持续文件锁会使服务保护性阻断读写；遇到该提示必须保留原文件和 `.workspace-restore`，排除权限/占用原因后重新预览，不能删日志强行继续。
