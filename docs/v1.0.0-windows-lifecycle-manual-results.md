## 首项 B03：取消预览且业务资料不变

1. 使用冻结 v1.0.0 和专用 Chrome profile，按 [隔离指南](v1.0.0-backup-restore-manual.md) 建立新的测试 DataRoot/RuntimeRoot。不要清空现有目标库或日常资料；自定义目录沿用隔离入口，不误开默认 CMD 的生产库。
2. 核对是空测试库，记下数量并另存一份导出基线。选择已核对来源/哈希的 [纯合成备份](fixtures/v1.0.0-workspace-backup.synthetic.json)，不修改原文件或业务 JSON，不调用真实 AI。
3. 进入「选择备份并预览恢复」，确认预览确实会新增记录，核对数量、来源、引用、容量和冲突提示。不能用本来无变化的预览来证明取消保护。
4. 点击「取消」，**不要点击最终恢复确认**。刷新页面，核对仍是空库、没有新业务记录或版本。
5. 再另存一份导出，与基线只读比较业务内容，忽略 `exportedAt` 等导出时间；不要改文件来消除差异。保留原合成备份，不能删除恢复日志来强行继续。
6. 回报 B03 的 PASS/FAIL/PENDING、实际日期、预览/取消后的数量、实际操作入口及问题。若有脱敏截图或日志再记录文件，未提供不补造。

B03 通过后，在同一隔离流程中准备一份含人工标记的旧备份，再保存更晚人工标记，执行 B04 的保留策略与二次确认，核对较新内容/历史仍在及实际成功/跳过/失败数量；不要选覆盖来“验证”。随后按原 B08 检查重复预览/恢复、重启及配对保持。这些目前仍 PENDING，不为归档自动填写结果，也不要求重复已确认的正常备份、配对、C08 或 W05/W06。
