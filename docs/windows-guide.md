# Windows 普通用户首次使用指南

适用于 ProductSpy 0.2.0 Windows x64 便携版。无需自行安装 Node.js、pnpm、数据库或 AI Key。需要 Windows 10 或更新版本的 x64 系统、系统 PowerShell 5.1，以及已安装的 Google Chrome；当前未发布 Chrome Web Store 版本，插件仍需按下面步骤手动加载。内置 Node.js 24.14.0 的 Windows 平台要求见 [官方平台表](https://github.com/nodejs/node/blob/v24.14.0/BUILDING.md#platform-list)，具体实际验收系统以本次报告为准。

## 1. 解压并启动工作台

1. 下载 `ProductSpy-0.2.0-windows-x64.zip`。本地构建产物位于项目的 `artifacts` 目录；公开下载以发布者实际上传的 GitHub Release 资产为准。
2. 右键 ZIP，选择「全部解压缩」，放到你准备保留的目录。**先完整解压，再运行；不要在 ZIP 压缩窗口里双击。**
3. 打开解压后的 ProductSpy 文件夹，双击 **ProductSpy.cmd**。
4. 启动窗口出现后，会自动启动本机工作台并打开浏览器。如果默认浏览器不是 Chrome，在 Chrome 地址栏输入 **http://127.0.0.1:3000**。

启动器使用包内 Node.js 和 Windows PowerShell 5.1，运行现有 Next.js 工作台，不会安装全局开发工具，也不需要管理员权限。窗口提供「打开工作台」「打开插件文件夹」「AI 设置」「打开用户数据」「停止并退出」。

再次双击启动文件不会新增第二个工作台服务。若 3000 端口被别的程序或源码开发服务占用，启动器会提示冲突；先退出占用程序，再重试。不要更改为其他端口，插件的工作台地址固定为 3000。

## 2. 加载 Chrome 插件

当前是商店发布前的手动安装版。Windows 便携包已带构建好的插件，不需要运行任何命令；Extension ZIP 是扩展提交材料，不是双击即可安装的 Windows 程序。

1. 在启动窗口点击「打开插件文件夹」，确认这里有 `manifest.json`。
2. 在 Chrome 地址栏输入 **chrome://extensions**。
3. 开启页面右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」。
5. 选择便携包中的 **extension** 文件夹，而不是外层 ProductSpy 文件夹，也不是 ZIP 文件。
6. 从 Chrome 工具栏的拼图按钮中找到 ProductSpy，将其固定到工具栏。

如果只下载了 `ProductSpy-0.2.0-extension.zip`，先把它完整解压到长期保留的文件夹，再加载包含 `manifest.json` 的那个文件夹。不要在加载后删除或移动文件夹，否则 Chrome 将无法继续读取扩展。商店正式发布后可改用商店安装，但这个版本没有可用的正式商店安装链接。

源码开发者加载的是 `apps/extension/dist`，普通便携用户加载的是 **extension**。开发者命令见项目 README 的「源码开发」部分。

## 3. 安全配对

1. 保持启动窗口运行，打开工作台。
2. 点击左侧「安装 Chrome 扩展」，或右上角扩展说明按钮。
3. 点击「生成配对码」，复制显示的码。
4. 点击 Chrome 工具栏 ProductSpy 图标，将码粘贴到「工作台配对码」。
5. 点击「连接工作台」，看到「工作台已连接」即可。

配对码有效 **2 分钟**，只能使用一次。过期时在工作台重新生成，不需要重装程序。配对码不是 Amazon 密码，也不是 AI Key。不要在公开截图或 Issue 中粘贴配对码、令牌、Cookie 或 Key。

重新配对会替换旧连接。更换插件安装目录、卸载后重新安装或扩展 ID 改变时，可能需要重新配对；已经保存在工作台的商品不会因此删除。工作台「撤销扩展连接」可取消旧令牌的授权。

## 4. 采集第一个 Amazon 商品

1. 打开 Amazon 商品详情页，等待标题、图片和当前变体加载完成。
2. 点击 ProductSpy 图标。首次使用时先阅读采集与保存说明，点击「同意并开始采集」，再检查标题、ASIN、价格和主图。
3. 点击「保存到素材库」。
4. 在工作台点击「商品库」，打开刚保存的商品。

没有商品时，工作台显示首次采集说明。搜索页、分类页或其他平台不会被识别为支持的商品页。遇到采集失败，可等待商品页加载，重新打开扩展并点击「重新识别」；验证码或地区限制需要按 Amazon 正常流程处理，ProductSpy 不绕过这些限制。

价格、图片、视频等取决于当前页面。显示「暂不可用」不代表自动填入估计值。切换尺寸或颜色后，等待页面稳定再采集。同一 ASIN 再次保存会更新原记录，不新增重复商品。

## 5. 分析商品

打开商品详情的 AI 分析标签，点击「开始 AI 分析」。没有配置 AI Key 时使用 **Mock 演示模式**：可以完整体验卖点、受众、营销角度、Hook、五段短视频脚本、图片和视频 Prompt，不会调用外部 AI 服务。

要使用自己的真实服务：

1. 在 ProductSpy 启动窗口点击「AI 设置」。
2. 选择模式，填写自己的 API 地址、模型名称和 Key。
3. 保存后，先「停止并退出」，再双击 ProductSpy.cmd 重新启动，使设置生效。
4. 回到商品详情发起分析；真实服务可能按其规则计费，文字资料会发送给你配置的服务商。

`auto` 表示有 Key 时使用真实服务，否则 Mock；`mock` 始终演示；`real` 强制使用真实服务，缺少 Key 时会给出配置错误。服务需兼容 `/chat/completions` 和 JSON response 格式，远程地址应使用 HTTPS。ProductSpy 不提供 Key，不把 Key 放入便携包或扩展。启动器用 Windows DPAPI 按当前用户保护 AI 设置；这不是商品文件的加密。

## 6. 断线、退出与数据保存

工作台未运行时，扩展保存的商品会暂存在 Chrome 本机存储中，并显示尚未同步。启动 ProductSpy 后，在扩展点击「重试同步」。如果连接已撤销，先重新配对再重试。**卸载插件会删除它的本地存储，因此请先同步待保存商品。**

浏览器标签页可以关闭；只有使用启动窗口「停止并退出」或关闭启动窗口，才会停止本机服务。停止工作台不会删除商品，下次启动后仍可查看。关闭浏览器和关闭工作台是两个不同操作。

## 7. 数据目录、备份和更新

用户资料与程序文件分开保存：

```text
%LOCALAPPDATA%\ProductSpy\
├─ data\       商品库与工作台配对配置
├─ settings\   当前 Windows 用户保护的 AI 设置
├─ logs\       本机启动与服务日志
└─ runtime\    本机运行状态
```

启动窗口的「打开用户数据」可直接打开这个位置。普通版不会将商品保存到解压后的程序目录；更新或更换程序目录不会复制空商品库覆盖已有文件。

备份商品时，先「停止并退出」，再复制 **data** 文件夹到自己的安全备份目录。这个目录含配对信息，也属于私有资料。AI 设置绑定当前 Windows 用户，直接复制加密设置到另一用户或电脑未必能解密，换电脑时应重新填写自己的 Key；扩展也需要重新配对。

更新步骤：

1. 在旧版本停止并退出，备份 data 文件夹。
2. 将新版完整解压到新目录，不需要删除 `%LOCALAPPDATA%\ProductSpy`。
3. 双击新版 ProductSpy.cmd，确认商品仍在。
4. 在 Chrome 扩展管理页更新加载目录或加载新版 extension，再按提示重新配对。
5. 确认更新成功后，才删除旧版程序文件夹；保留需要的备份。

没有自动更新器或付费安装器。当前商品 JSON 结构延续既有模型，兼容性由更新测试验证；遇到无法读取的旧数据会报错保留原文件，不会静默清空。彻底清理用户数据需要你先停止服务并自行删除上述用户目录；删除程序文件夹本身不会删除素材库。

源码用户原默认数据在 `apps/web/.data`。便携版不会偷偷读取或搬走该目录。需要迁移时，先停止源码和便携版两个服务，分别备份原 `.data` 与目标 `data`；**仅在目标还没有自己的商品或配对数据时**，将原 `products.json` 和存在的 `.bridge-credentials.json` 复制到便携版 `data`。不要复制临时文件，不要覆盖已有新商品库。目标已经有数据时保留双方备份，当前没有自动合并两个商品文件的功能。

配对配置绑定扩展来源；保持原扩展 ID 和本机令牌时可以沿用，更换扩展目录或重新安装后可能仍需重新配对。不要从源码目录复制 `.env.local`、API Key、浏览器 profile 或运行日志到程序包。DPAPI 设置绑定原 Windows 用户，换用户 / 电脑时应重新填写 Key。不要把商品、令牌配置或密钥粘贴到 GitHub。

## 常见问题

| 提示 / 情况                  | 操作                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 工作台打不开 / 3000 端口冲突 | 退出已运行的开发服务或其他占用程序，再启动；启动器不会终止别人的进程。                                         |
| 点击 ProductSpy.cmd 无法运行 | 确认完整解压、Windows x64 与 PowerShell 5.1 可用。公司策略禁止脚本时联系管理员，不能把此问题当成插件采集失败。 |
| Windows 提示未知发行者       | 当前便携程序未做商业代码签名。核对下载来源与 SHA-256；此提示不代表已获得 Windows 或商店审核认证。              |
| 插件「工作台未启动」         | 双击 ProductSpy.cmd，保持启动窗口运行，再点击「重试同步」。                                                    |
| 配对码失效                   | 在工作台重新生成，2 分钟内填入扩展；不要重复使用旧码。                                                         |
| 商品采集失败                 | 确认是 Amazon 商品详情页，等待加载并重新识别；遇到验证码按 Amazon 正常流程处理。                               |
| AI 未配置                    | 使用 Mock 即可完整演示；真实模式要配置自己的服务并重启工作台。                                                 |
| 更新后商品不见               | 在「打开用户数据」检查 data 目录和备份，不要先删除目录；确认使用的是同一个 Windows 用户。                      |

隐私详情见 [PRIVACY.md](../PRIVACY.md)。测试结果与 Chrome 稳定版待验收项见 [Phase 10 报告](phase10-validation.md)；不能把 Chrome for Testing 自动化结果当作正式 Chrome 人工验收。
